# 历史搜索、通知偏好、快捷记忆与任务模板

四项功能对新老用户开放，也可在未连接微信时通过网页管理。所有搜索与设置只作用于自己的助手；管理员不能通过这些新接口跨用户操作。

## 历史搜索

网页侧栏「搜索历史」支持关键词查询、继续加载和点击结果查看原文及前后消息、下载原附件。搜索普通对话与任务结果，排除快捷命令回执，避免搜索结果反复命中自身。附件正文和记忆文件不包含在消息搜索中。

- `/search 项目计划`：最近 5 条命中；更多结果使用回执中的游标命令。
- `/message 123`：查看搜索结果中的消息编号；较长原文与上下文在网页查看。
- 查询按连续子串匹配，`%`、`_` 作为字面文字，不作为通配符；关键词最长 100 字符。
- 网页 API：`GET /api/assistants/:id/history/search?q=关键词&before=消息序号`，每页 10 条；`GET /api/assistants/:id/history/context?seq=消息序号` 返回定位消息及附近上下文。

## 通知偏好

网页侧栏「通知偏好」，或以下命令：

| 命令 | 效果 |
| --- | --- |
| `/notify` | 查看当前设置 |
| `/notify quiet 23:00 08:00` | 北京时间 23:00 至次日 08:00 免打扰，包含开始、不包含结束 |
| `/notify quiet off` | 关闭免打扰，等待的通知恢复投递 |
| `/notify final on` | 平台自动进度只留网页，微信发送最终回复 |
| `/notify final off` | 恢复推送自动进度 |
| `/notify digest 30` | 将等待的任务文字合并成简短摘要，最早一条等待 30 分钟后开始合并 |
| `/notify digest off` | 关闭合并，尚未合并的任务文字恢复逐条投递 |

默认全部关闭，升级不会改变现有用户的推送习惯。设置持久化在 SQLite，重启保留。免打扰只延后平台自动回复和自动任务结果；网页仍即时显示完整结果。命令回执、网页输入镜像及普通聊天中主动调用发送工具的消息不受影响。独立邮件镜像暂不在这组偏好范围内。

轻量提醒也遵循免打扰和摘要设置，不能同时承诺提醒准点推微信。附件不进入文字摘要，但自动任务附件仍遵循免打扰。摘要最多合并 3 条待发文字、每条摘取前 260 字；较长或更多内容可形成后续摘要，完整结果始终保留在原消息和任务执行记录里。摘要是确定性的摘录，不启动额外模型。

合并时原投递回执标为「已跳过」，原因记录对应摘要 ID；真正的微信发送结果在摘要 outbox 回执中，不把合并当成微信已接收。摘要正文和投递记录同时落库，重启不重建已合并内容。队列约每 10 秒重新检查可投递项，仍遵循微信连接和回复额度限制。已经发送的内容不会撤回，已经形成的摘要不会在关闭合并后展开重发。

API：`GET/POST /api/assistants/:id/notifications`，字段为 `quiet: null | {start,end}`、`finalOnly: boolean`、`digestMinutes: 0..1440`；POST 可只提交要修改的字段。

## 快捷记忆

- `/memory` 或 `/memory list 2`：列出根目录记忆文件和 memory/ 第一层文件，6 条一页。完整目录和子目录在网页「文件与记忆」中查看。
- `/memory add 回复简短，先说结论`：保存一条快捷记忆，最多 2000 字节；最多保留 100 条快捷记忆。
- `/memory show MEMORY.md`：预览指定记忆文件。
- `/memory delete 记忆ID`：使用列表返回的删除命令，只删除快捷创建的那一条；原有 MEMORY.md、AGENTS.md 仍通过网页编辑。

快捷记忆存为现有工作区 `memory/quick-<请求摘要>.md`，沿用每轮记忆读取、网页预览和编辑、路径隔离、版本冲突检查及修改前备份。从操作成功后的下一轮开始读取最新文件；旧对话仍然保留，不代表删除文件能抹去所有历史上下文。

文件与 SQLite 不能共享事务，因此先持久化操作意图与目标版本，再修改文件并保存回执。相同输入重试使用同一文件名和意图；文件成功后回执失败可恢复，不额外创建文件、不覆盖后来编辑的内容。删除重试保留原版本约束。此机制不改变原有任务/通知命令的 SQLite 事务。

## 任务模板

网页「自动任务」可选择模板、填写主题、点击「填入模板」，再调整时间或内容。「预览时间」使用正式调度器计算接下来的最多 3 次时间，不创建任务；「创建任务」才保存。

| ID | 模板 | 默认规则 |
| --- | --- | --- |
| morning | 晨间简报，带资料链接和日期 | 每天 09:00，智能任务 |
| weekly | 按工作区记录总结进展，不虚构记录 | 每周五 18:00，智能任务 |
| watch | 检查指定网页并汇报当前内容 | 每天 09:00，智能任务 |
| reminder | 原样发送一段提醒 | 周一至周五 15:00，轻量提醒 |

`/templates` 列出模板，命令示例：

```text
/template morning preview 09:00 科技动态
/template morning create 09:00 科技动态
/template weekly preview 18:00 工作进展
/template watch preview 09:00 https://example.com
/template reminder create 15:00 喝水休息
```

命令默认北京时间；网页可调整时区和规则。预览是当前时间下的估算，创建时会重新计算。创建仍受任务数量、幂等请求、微信连接和投递限制约束。

网页巡检模板每次均汇报，不包含「只有变化才通知」的持久化条件订阅；后者不属于本次四项功能。

## 验证与部署

新增行为验证：`node --test test/platform/workspace-upgrades.test.js`。浏览器：`node scripts/test-platform-workspace-upgrades-browser.mjs`。同时运行平台和核心回归。

不新增表或依赖，偏好和记忆操作意图复用 settings，摘要复用 messages/outbox。回滚源码前应处理正在等待的免打扰/摘要队列：旧版本不识别新通知偏好，可能立即投递等待内容。保留当前数据库及用户记忆文件，不能用旧备份覆盖新历史。
