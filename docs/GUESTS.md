# 游客使用与账号绑定

未登录时，打开网站直接进入助手主页，自动获得属于当前浏览器的游客空间。已登录用户继续进入自己的账号空间。游客可以扫码连接微信、聊天、上传文件、管理记忆、自动任务、待办和收藏；智能聊天同样需要先连接微信。

左下角显示「绑定账号，保留你的资料」，手机端位于侧边栏底部。点击「绑定账号」设置一个未注册的用户名及密码，会将当前游客原地升级成普通账号，保留用户 ID、助手 ID、微信绑定、模型线程、对话、文件、记忆、任务、待办、收藏和通知设置，不需要重新扫码。当前页面未发送的草稿也保留。

「已有账号？登录」会切回已有账号的空间，不合并或覆盖双方的数据；退出已有账号后，返回该浏览器原来的游客空间。游客升级为账号后，旧游客凭证失效，后续访问使用账号登录。多标签页通过浏览器通知同步账号切换；首次访问在支持 Web Locks 的浏览器中串行创建游客，避免重复空间。

游客凭证保存在 HttpOnly、SameSite=Strict Cookie，HTTPS 部署启用 Secure，最长有效期 30 天。刷新、重开网页、服务重启期间，只要凭证仍有效，就会回到原空间。清除浏览器数据、更换浏览器或凭证过期后，未绑定账号的空间可能无法找回；这不意味着服务会自动删除原始数据。建议在长期使用前绑定账号。注册账号的登录会话仍为 7 天。

## 隔离与持久化

复用 `users.role='guest'` 和现有会话/助手表，无需新增表。游客没有可用于密码登录的凭据，不能访问管理员接口或修改密码；用户提供的角色、用户 ID 或助手 ID 不会用于创建或认领身份。微信同一绑定不能被其他空间接管，已有账号已绑定的微信应回到原账号使用。

`POST /api/guest` 检查当前有效会话，再尝试恢复本浏览器仍有效的游客凭证，最后才创建新游客。创建受来源校验、操作校验标识和速率限制保护；当前版本每个对端地址每小时最多创建 60 个新游客，已有会话及恢复不消耗该额度。部署在反向代理后，对端可能为代理地址，此限制是进程级保护，不是精确的访客统计。

绑定通过 `POST /api/register` 原地升级，前端带 `bindGuest:true` 防止会话失效时误建另一个空间。用户名更新、密码设置、原游客会话撤销、新会话创建和审计在同一事务中完成，提交成功后才写入 Cookie；同名账号或并发冲突不会改动游客空间。已有账号登录保留单独的游客恢复 Cookie，它只能恢复仍为游客的身份，不能恢复已升级账号。绑定后的旧凭证和伪造凭证都不能认领账号。

相关测试：`node --test test/platform/guest.test.js`、`node scripts/test-platform-guest-browser.mjs`。浏览器验收包括游客主页、扫码前无需账号、绑定保留会话及草稿、已有账号切换、返回游客、多标签页同步和手机侧栏。

发布前在 sg 备份 SQLite，并在空闲时重启单一平台服务。回退旧代码不会删除已绑定账号和历史数据，但旧前端不提供游客恢复入口；应优先修复前向版本，不通过恢复旧数据库覆盖新增用户数据。
