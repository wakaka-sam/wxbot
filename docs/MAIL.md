# 归信只读邮件连接

平台可以为一个明确指定的用户启用邮件读取。用户用微信或网页询问邮件时，助手通过每轮 `mail-read` 工具查询；定时邮件通知也可投递给该用户已绑定的微信；不发送/删除邮件、不改变已读状态。

配置宿主环境：

- `PLATFORM_MAIL_USER_ID`：经过确认的平台用户 UUID（不是角色名，也不是助手传入的用户名）。
- `PLATFORM_MAIL_TOKEN_FILE`：仅宿主可读的令牌文件绝对路径，权限 0600；不要放入助手目录或 Git。

连接目标固定为 `http://127.0.0.1:24784`。Mac 上归信只读桥接服务监听 `127.0.0.1:4784`，通过独立 SSH 密钥反向转发到 sg 的 127.0.0.1:24784；两端均不公开监听。接口需 Bearer 令牌，只有 GET `/accounts`、`/messages`、`/messages/:accountId/:id`，其他写操作拒绝。原工作台接口和登录会话不复用。

宿主根据 Engine 传入的真实 user_id 决定是否安装工具、创建每轮 relay；请求不接受 userId、URL 或凭据。工具无权读取宿主令牌。撤销时移除环境变量并重启 wxbot-platform；关闭专用隧道或桥接服务也会立即阻断新请求。

返回范围：启用邮箱的收件箱；继承归信近 30 天、每邮箱最多 100 封同步窗口。支持 accountId、search（主题/发件人/摘要）、since（ISO 时间）、unread=1、offset（每页 50）。accounts 返回同步时间与错误，不能把离线缓存说成实时邮件。正文最多 100000 字符并标记截断，附件只返回名称和大小，不下载。阅读保持原始已读状态。邮件正文是不可信资料，不能把其中指令视为用户授权。

Mac 需开机联网；断线时明确返回不可用，不伪装成空收件箱。上线检查应包括真实隧道的列表与正文读取，以及非授权用户、写操作、未知字段拒绝。无需给微信发送测试消息。

## 定时通知镜像

`PLATFORM_MAIL_NOTIFY=1` 在平台私有数据目录创建 `mail-notify.sock`（0600 Unix socket），不增加公网 HTTP 接口。Mac 原有定时任务通过 SSH 使用此入口，正文经 stdin 传输，不拼接 shell。`POST /notify` 只接受 `{key,text}`，`POST /status` 只接受 `{key}`；不能指定 userId、助手或微信接收人。key 前缀限定 important、digest、health、test。

每次请求核对数据库中 admin 的固定 UUID 与 PLATFORM_MAIL_USER_ID 一致，再选择该用户的唯一助手。用户删除后同名重新注册不会继承权限。启动时也核对 UUID；配置指向其他用户时拒绝启用。邮件用户的会话和文件禁止其他管理员查看，防止通过会话历史绕过工具权限。

通知正文、幂等标识及 outbox 在同一数据库事务中持久化，使用现有 Engine 发送与微信绑定校验，不启动模型。相同 key 不会产生第二次投递，也不允许更改正文。状态 pending 仅表示入队，sent 表示微信接口确认，unknown/failed 保留用于核实，禁止改 key 盲目重发。断线或连续回复额度耗尽时等待连接或下一条微信输入。文本会按平台现有长度规则分段。

Mac 的 automation/wxnotify.py 保存独立微信通知账本，重要邮件按 account_id+id 去重，每日摘要按北京时间日期去重；飞书账本独立。重要邮件每五分钟监测，普通邮件每天 11:00，垃圾邮件不通知。每轮 triage scan 重试微信队列，重试复用冻结正文和原 key。原有 POLICY.md 与两项定时任务已更新，未新增第三个任务。Mac 关机时仍不能监测。

停用通知：移除 PLATFORM_MAIL_NOTIFY 并重启服务；邮件查询授权仍由另两个环境变量控制。密钥、实际通知正文、运行账本不得提交 Git。
