# 自动任务

所有新老用户均可使用，无需管理员单独开通。在微信或网页聊天中直接告诉助手，例如：

- “30 分钟后提醒我休息。”
- “每天北京时间早上 9 点提醒我喝水。”
- “每周一下午 6 点整理本周待办。”
- “每隔 2 小时检查这个网页，有变化就告诉我。”
- “看看我的自动任务”“暂停那个喝水提醒”“取消任务”。

也可从网页侧栏「自动任务」创建、查看、暂停、恢复、取消任务。该面板在微信未连接时仍可管理任务。聊天工具会返回任务 ID、规则和下次执行时间；仅口头答应、写入记忆文件不代表创建成功。

## 时间与执行规则

- 一次性任务须在未来一年内；固定间隔最短 1 分钟。每人最多保留 20 个未结束任务（含暂停和排队的一次性任务）。列表保留展示最近 100 项，未结束任务优先。
- 每天、每周规则支持 IANA 时区，默认 `Asia/Shanghai`。网页一次性时间使用北京时间；聊天工具的一次性 ISO 时间必须包含 `Z` 或 UTC 偏移。星期 0 为周日。
- 调度器每 10 秒检查一次。任务在用户自己的助手会话里串行执行，与普通聊天分开排队，不打断当前回复。模型使用当前执行时间，而非旧会话日期。
- 微信未连接时暂缓执行，连接恢复后再运行。错过的周期合并为一次，每个任务至多一个正在执行或等待执行的作业。间隔任务保留最初的时间基准。
- 夏令时跳过不存在的本地时间；重复出现的本地时间只使用第一次，避免同一天执行两次。
- 任务结果保存到网页会话，并通过原有微信发送队列投递。微信回复额度耗尽时结果留在队列，用户再发一条微信消息可继续接收；不能保证准点送达微信。
- 暂停、取消会取消已排队但未开始的作业；已经运行的作业允许完成。如需中断当前执行，用聊天中的停止回复。取消后不能恢复，应重新创建。
- 服务重启保留规则和待执行作业。已经开始执行的作业若在重启时中断，会标记为中断，**不自动重试**，以免重复执行外部操作。失败同样不自动重试；循环任务仍按下一周期执行。可在任务列表查看最近执行状态。
- 一次性任务入队后显示“等待执行”，结束后显示“已结束”；最近执行状态区分成功、失败、中断。任务列表的执行成功不等于微信投递成功，微信投递仍以发送队列状态为准。

## 工具与接口

每轮输入均附带当前工具的完整参数说明，兼容升级前创建的旧会话；也可运行 `wxbot-schedule --help` 查看完整一次性示例，不需要轮次标识。参数校验失败会指出允许字段并提示帮助入口。

每轮提供私有 `wxbot-schedule --turn <本轮 UUID>`，stdin 接收 JSON：

```json
{"action":"add","requestId":"unique-request-123","name":"喝水提醒","prompt":"提醒我喝水","spec":{"type":"daily","time":"09:00","timezone":"Asia/Shanghai"}}
```

其他规则：`{"type":"interval","minutes":30}`、`{"type":"weekly","weekday":1,"time":"09:00","timezone":"Asia/Shanghai"}`、`{"type":"once","at":"2027-01-01T09:00:00+08:00"}`。

查询：`{"action":"list"}`。管理：`{"action":"pause","id":"任务UUID"}`，action 也可为 `resume` 或 `remove`。add 重试必须复用相同 requestId；同一标识更改内容会被拒绝。不要把任务正文拼进 shell 命令。

已登录网页通过 `GET /api/assistants/:id/schedules` 查看、`POST` 同一地址提交上述 JSON（需既有 CSRF 标识）。只允许所有者访问，包括管理员也不能读取他人的任务列表。

## 隔离与持久化

规则和作业保存在原平台 SQLite 数据库。新增 `schedules` 表，`jobs` 增加 `schedule_id`、`scheduled_for` 及唯一索引。事务同时提交作业和下一执行时间，重复扫描不能重复排队同一轮。

宿主从当前执行器绑定助手身份，不接受助手传入接收人或用户 ID。文件 relay 使用当前轮次能力、目录 FD 锚定和 symlink 拒绝；本轮结束后失效。自动任务执行期间只能查询任务，不能递归创建或修改任务。任务不会获得额外账号授权，也不能访问其他用户工作区。

验证：`npm run check`、`npm test`、`npm run test:platform`。真实隔离执行器验收：在 sg 加载现有部署环境后运行 `PLATFORM_AGENT_TEST=1 node scripts/test-platform-schedules.mjs`，仅使用临时合成用户、模拟微信通道和独立模型会话，退出清理。

部署回滚若需切换到不支持自动任务的旧代码，应先停止平台，将未开始的 `kind='schedule'` 作业标为 cancelled、活动规则标为 paused，再切回旧版本启动。保留新增表和列即可；不要把旧数据库备份直接覆盖回线上而丢失新会话。

旧会话升级验收可额外设置 `PLATFORM_LEGACY_HARNESS=/隔离旧版本/src/platform/adapters/codex.js`，脚本会先创建旧版会话再用新版恢复同一 thread，验证创建和到点执行；仍仅操作临时测试数据。
